# AI 英语口语陪练项目规划

## 1. 项目定位

本项目是一款面向英语口语练习的 AI 陪练工具，目标是在指定场景下帮助用户完成真实对话训练，并在练习结束后提供可量化、可复盘、可持续改进的学习反馈。

三天 MVP 的核心不是做一个普通语音聊天应用，而是完成一个清晰的口语训练闭环：

选择场景 -> 实时语音对话 -> 课后总结 -> 关键句复练 -> 弱点记忆。

## 2. MVP 范围

三天内优先实现以下能力：

- 场景选择：面试、点餐、商务会议。
- 实时语音对话：用户与 AI 进行英文语音交流。
- 延迟纠错：自由对话中不频繁打断，课后统一给出语法和表达反馈。
- 发音评测：对关键复练句进行发音、准确度、流利度、完整度评分。
- 课后总结：输出总分、WPM、填充词比例、语法错误率、表达优化建议。
- 弱点记忆：记录用户高频问题，用于下一次练习的针对性训练。

## 3. 暂不纳入 MVP 的内容

以下内容作为后续优化方向，不放入三天核心交付：

- 自研发音模型或 GOP 音素级算法。
- 自研 WebRTC 中继或低延迟音频基础设施。
- Qdrant 等长期向量记忆系统。
- 摄像头眼动、表情或情绪识别。
- TOEFL / IELTS 官方认证级评分。
- 完整用户登录、支付、班级或后台管理系统。

## 4. 技术路线

默认技术栈：

- 前端：React + Vite + TypeScript。
- 后端：FastAPI。
- 实时语音：OpenAI Realtime API + WebRTC。
- 发音评测：Azure Speech Pronunciation Assessment。
- 数据存储：SQLite。
- 用户模式：MVP 阶段使用单用户 `demo`。

后续如时间充裕，可扩展为 PostgreSQL、多用户账号体系和长期学习档案。

## 5. UI 方向

UI 采用年轻游戏化学习工具风格，避免做成营销页。

关键原则：

- 首屏就是场景工作台，用户能直接开始练习。
- 视觉明亮、轻快，有分数、徽章、进度和复练任务等轻量游戏化反馈。
- 控制复杂度，不做积分商城、角色养成等重系统。
- 桌面端和移动端都必须保证文本不重叠、不溢出、按钮可点击。

## 6. 三天排期

### Day 1

- 初始化 FastAPI + React 项目骨架。
- 实现场景选择与 Session 创建。
- 初步接入实时语音会话。

目标：用户能选择场景并进入语音练习页。

### Day 2

- 保存对话转写。
- 生成课后总结。
- 接入关键句发音评测。
- 实现报告页和复练入口。

目标：用户能完成一次练习并看到结构化反馈。

### Day 3

- 实现弱点记忆。
- 打磨 UI、空状态、加载态、错误态。
- 准备 3 个演示场景和兜底数据。

目标：形成稳定可演示版本。

## 7. 任务与 PR 规则

任务按以下顺序推进：

1. 初始化 FastAPI + React 项目骨架。
2. 实现场景选择与 Session 创建。
3. 实现 OpenAI Realtime 会话代理。
4. 实现对话转写保存与练习房间 UI。
5. 实现课后报告生成。
6. 实现报告页可视化。
7. 实现 Azure 发音评测。
8. 实现关键句复练 UI。
9. 实现 Learner Profile 弱点记忆。
10. 演示稳定性与 UI 打磨。

每个 PR 只做一件事。每完成一个任务后先暂停汇报，由项目负责人决定是否修改、是否创建 PR、是否继续下一项。

PR 描述必须包含：

- 功能描述：说明功能作用和使用方式。
- 实现思路：说明核心技术路径。
- 测试方式：说明如何验证功能正常运行。

## 8. 验收标准

基础 MVP 至少应满足：

- 用户可以选择一个场景并开始练习。
- 用户可以与 AI 进行英文语音对话。
- 练习结束后可以看到课后总结。
- 总结中包含至少 3 个量化指标。
- 系统可以抽取关键句并进行发音复练。
- 下一次练习可以读取上一次的弱点记录。
- 页面在桌面端和移动端均无明显布局问题。

## 9. 竞争力表达

本项目的核心竞争力不在于单点功能堆叠，而在于学习闭环：

- 对话中保持自然交流，减少即时打断。
- 课后集中纠错，降低用户表达焦虑。
- 用 WPM、填充词、错误率等指标量化进步。
- 用关键句复练把反馈转化为行动。
- 用弱点记忆让下一次练习更有针对性。

这使系统更像一个持续陪伴的口语教练，而不是一次性的 AI 聊天工具。
